# 路漫漫

> `life-path-stories` · 课程结课项目

「路漫漫」—— 让人匿名写下自己正走在人生哪一段、卡在哪、后来怎么样。

不做关注、私信、好友关系，也不提供心理建议。它只做一件事：让正在某段路上的人，看见走过来的人留下的路标。

### 关于 `cloud-config.js`

这个文件里的 `endpoint` 与 `publishableKey` 是**可公开的应用标识**，不是密钥：任何部署到浏览器上的前端都必须内置它，打开控制台就能看到。

真正的权限不在这里——接口全部走 `SECURITY DEFINER` 函数，表对前端零授权。拿走这个标识最多能调用公开函数，改不了任何一行数据。

### 关于访问口令

V1.4 之前，站点外面套了一层访问口令（路演前防止内容被随手写脏）。路演准备阶段已经取消，观众扫码直接进入内容。

取消是**配置驱动**的，代码里的分支都还在：`api_gate_verify` 与 `api_session_init` 只在 `app_config.gate_pass_hash` 非空时才校验。想恢复口令，把 hash 写回那张表即可，前端也不需要改——`api.js` 里的 `ensureSession` 会自动重新要求过门。

### 关于管理入口与投稿开关

产品没有账号体系（一个浏览器 = 一个身份），所以「管理员」不是一个用户，而是**一个 bcrypt 口令**：`/admin.html` 输入口令后可以开关投稿、隐藏 / 恢复 / 删除内容。口令只存在页面内存里，关掉标签页就要重新输入；连续错 8 次锁 5 分钟。

之所以不给某个设备开管理员权限：换浏览器、清缓存、换微信环境就失效，现场演示时最容易翻车的位置恰恰是这个。

投稿开关是**运行期**的，不看代码、不用重新发布：`app_config.publish_open` 为 `'0'` 时，首页的「+」与「写下我的这一段」由 `boot.js` 隐藏，`write.html` 显示提示并禁用「预览」，而 `api_story_create` 会直接返回 `43001`——绕开页面调接口也写不进去。三道防线缺一条都能被绕过，所以三条都留着。

## 三个设计要点

### 没有账号，靠设备身份

产品要求「点开链接就能用」，所以不做注册登录。一个浏览器 = 一个身份，凭证存在本地；换设备靠 12 位恢复码迁移。

判权只看内容表里的 `author_id`，不看设备。这样换设备时只更新用户表一行，内容表零改动。

### 服务端逻辑写在数据库函数里

托管平台不提供自定义服务端（没有 Node / Edge Function），业务逻辑只能落在 PostgreSQL 函数中，前端通过 `rpc()` 调用。

因此接口不是 REST 路径，而是 31 个 `api_*` 函数。表对前端**零授权**，只授函数执行权限——「前端只调函数、不碰表」不是约定，是数据库强制的。

### 错误不走 HTTP 状态码

函数改不了 HTTP 状态码，所以所有响应都是 200，业务结果放在响应体的 `code` 字段里。

前端在 `api.js` 的唯一出口把 `code ≠ 0` 转成异常，页面拿不到 `code`，也就写不出「忘了判断」的代码。

取舍与已知弱点（含 token 存 localStorage 的 XSS 风险）写在详细设计 2.11 与 5.5，没有回避。

## 匿名与通知的边界

点赞会让作者在首页铃铛收到一条「有人给你的路标点了赞」。接口内部确实带回了操作者的昵称字段，但**前端一处都不渲染**——匿名是这个产品的前提，作者只知道「有人走过」，不知道是谁。

个人空间里的「赞过的 / 收藏 / 浏览记录」只有本人可见，查的是本机设备身份，不对外暴露。

## 本地预览

在 `app/` 下起任意静态服务即可，例如 `python -m http.server 8080`，再打开 `http://127.0.0.1:8080/index.html`。

> 不建议双击 `index.html`：`file://` 下 origin 为 `null`，云服务客户端的跨域请求会被拒。页面用普通 `<script>` 而非 ES module，是为了避开另一层 CORS 限制。

## 部署

站点以纯静态方式托管在云应用平台上，仓库里的 `app/` 就是发布目录（`assets/` 与 `robots.txt` 需要带分享凭证才会放行）。

分享链接与二维码**不放进仓库**：两者都含分享凭证，二维码图片本身也被 `.gitignore` 忽略。需要给别人看时，另行发送链接或图片即可。

## 未完成

- **没有逐条审核**：投稿开关只控制「能不能发」，开着的时候内容直接写库并立刻公开，新帖排在列表第一位。`story.needs_review` 只会被写入（命中自伤关键词时置 1），列表与详情都不读它，所以它现在不挡任何内容；真正能挡的只有 `status='hidden'`，需要人工在管理页处理。
- **发帖限流按设备**：`rate_limit` 以 device_id 为 subject，每台设备 10 分钟 3 条；清掉本地身份换个设备号即可绕过。没有验证码，也没有全局频率上限。
- 联系方式拦截（R6-8 / E6-6）：服务端只有情绪危机的标记位，没有手机号 / 微信 / 邮箱的检测与高亮
- 草稿只留一份：PRD R6-9 要求最多 3 份、保留 7 天，当前是单份、不清过期
- 字数不足时按钮不置灰：只在提交那一刻校验（E6-2）
- 举报（F11）与内容处置后台（F13）：没有后台界面，处置只能直接改数据库
- PRD 文档尚未同步「5 个主题」，也未回填实测中发现的 DC-17 逻辑矛盾（示例内容计入列表却不计入条数）
