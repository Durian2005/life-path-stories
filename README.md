# life-path-stories

「人生的路你走到哪了」—— 让人匿名写下自己正走在人生哪一段、卡在哪、后来怎么样。

不是社交产品，也不提供心理建议。它只做一件事：让正在某段路上的人，看见走过来的人留下的路标。

## 三个设计要点

### 没有账号，靠设备身份

产品要求「点开链接就能用」，所以不做注册登录。一个浏览器 = 一个身份，凭证存在本地；换设备靠 12 位恢复码迁移。

判权只看内容表里的 `author_id`，不看设备。这样换设备时只更新用户表一行，内容表零改动。

### 服务端逻辑写在数据库函数里

托管平台不提供自定义服务端（没有 Node / Edge Function），业务逻辑只能落在 PostgreSQL 函数中，前端通过 `rpc()` 调用。

因此接口不是 REST 路径，而是 14 个 `api_*` 函数。表对前端**零授权**，只授函数执行权限——「前端只调函数、不碰表」不是约定，是数据库强制的。

### 错误不走 HTTP 状态码

函数改不了 HTTP 状态码，所以所有响应都是 200，业务结果放在响应体的 `code` 字段里。

前端在 `api.js` 的唯一出口把 `code ≠ 0` 转成异常，页面拿不到 `code`，也就写不出「忘了判断」的代码。

取舍与已知弱点（含 token 存 localStorage 的 XSS 风险）写在详细设计 2.11 与 5.5，没有回避。

## 本地预览

双击 `app/index.html` 即可。没有构建步骤、没有依赖、不需要起服务。

> 用了普通的 `<script>` 而不是 ES module，就是为了让双击能打开——`file://` 下浏览器会以 CORS 为由拒绝加载相对模块。

## 关于素材与生成标识

`app/assets/hero.jpg` 是 AI 生成的示意插画（OpenAI gpt-image，2026-10-15），文件内保留了 C2PA 内容凭证，未做任何抹除。用于演示版式，可随时替换为自有素材。

`docs/` 下的 PRD 文档同样保留了生成工具写入的 AIGC 元数据（`docProps/custom.xml`），未做抹除。产品设计与人写的内容由项目组负责，工具标识照实保留。
